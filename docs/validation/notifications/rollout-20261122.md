## New regressions

- Plan response still resolves after checklist changes, future rescheduling after
  the former time, and declining a proposed change to an elapsed agreed Plan.
  Cancellation supersedes the earlier invitation/response.
- Authenticated feature-card reservation is creator/current-room scoped,
  idempotent and independent of the later chat-card acknowledgment. Matrix ingress
  accepts one event per key; forged/reused/old-epoch markers cannot suppress a
  new ordinary chat alert. Category opt-out is not bypassed by the marked card.
- The actual Trixnity send serializer preserves the opaque marker, stable Matrix
  transaction ID and standard encrypted envelope. Stock older-client decoding
  restores the original envelope. No private content is put in the marker.
- New Challenge/Spark/Moment/note/status/idea/sharing producers, quiet delivery,
  hourly status limit, private thread access after Moment expiry, current blocks,
  stale resources, transaction rollback and old-client preference preservation.
- Different chat/activity resources and Moment/note IDs receive distinct OS tags.
- New routes reject incomplete/invalid targets. Idea taps do not mutate interest
  or create a Plan. Private thread UI uses authoritative reply permission and
  clears private data on background or session change.
- Settings retain confirmed values after failed writes and remain scrollable with
  dark mode, narrow width and enlarged text. New category opt-ins start off.

The existing Moment query-count regression caught and prevented a per-note query
increase: reply permission is annotated in the authorized queryset. The full suite
passes after that correction.

## Deployment and remaining coverage

Apply additive backend `notifications.0005` and restart the backend/worker before
installing this Android build. New destinations require `notification-catalogue-2`.
Upgrade feature-card senders too: older unmarked senders can still cause duplicate
domain/chat alerts. The backend's
[catalogue and deployment guide](https://github.com/SrizanKhadka/SriSu/blob/codex/notification-rollout/docs/notification-rollout.md)
documents policy, TTL, compatibility and rollback order.

Windows deployment, real Firebase delivery, device sound and actual locked-phone
notification taps were **not** repeated for this rollout. The October physical
device records validate their recorded revisions only. Normal-priority quiet
activity can be delayed by Android; offline activity may coalesce under the
existing provider collapse keys. Apple enrollment/APNs remains skipped.
